# 插件拆分实施记录

日期：2026-10-12。实现依据：[拆分方案](./dsh-plugin-refactor-plan.md)。本地实施，不提交、不发布、不部署。

## 已落地的结构

- `dsh-agent-runtime` 拥有 Harness、原生会话、运行实例、能力组装、历史、流与取消接口。
- `dsh-agent-settings` 拥有用户能力、MCP、偏好存储和设置 API；能力与模型偏好界面也移入此包。
- `dsh-execution-environment` 拥有 Python 环境、依赖检查、公共 Skills 和管理员环境界面。`dsh-document-tools` 保留为兼容导出。
- `dsh-app-sync`、`dsh-collaboration`、`dsh-device-services` 分别拥有同步、协作、通知与设备动作实现及其生命周期。
- 账号、模型配置、悬浮界面、应用平台、应用开发继续分别使用现有插件。
- `app-foundation` 是共享应用数据、包、文件与权限实现的内部库；`ui` 是共用 shadcn/ui 组件库。两者不提供额外 Server 或产品入口。
- 旧包的子路径导出保留为转发；已有 API、存储路径和加密格式保持兼容。
- npm 包增加新插件的导出，仍只安装一个 LocalApp 包。插件构建顺序统一由 `scripts/build-plugin-packages.mjs` 管理。

为消除同步与平台之间的循环依赖，增加了共享应用库；这属于方案中公共接口的实现调整，不增加插件数量。账号包的直接依赖由 134 项减少至 14 项，Agent 相关依赖归执行插件。

统一 Server 在关闭网络连接前先停止插件，避免等待仍然存活的事件流、MCP 和会话连接。测试使用同一份已编译模块，避免跨包错误类与数据库实例重复。

## 可选能力

程序接入使用 `synchronization`、`collaboration`、`deviceServices` 选项。Server 支持对应环境变量：

| 环境变量 | 设置为 `0` 的效果 |
| --- | --- |
| `LOCALAPP_APP_SYNC` | 不加载应用同步，不注册同步接口；隐藏对端导航 |
| `LOCALAPP_COLLABORATION` | 不创建协作处理器，协作接口不可用 |
| `LOCALAPP_DEVICE_SERVICES` | 不加载通知与设备服务，相应接口不可用；隐藏对应导航 |

默认保持原有完整体验。原有 `LOCALAPP_AGENT_UI`、插件组合与公共 Skills 开关继续可用。上述新开关暂时通过启动配置使用，不增加管理员页面控件。

## 社区插件

检查了 npm 发布的 `@js2hou/dsh-mcp-manager@0.1.5`：需要 `connection`、`loader`、`tools`，通过 `connection.rpc.handle` 提供入口，并直接编辑 profile 的 YAML 文件、从 loader 枚举 MCP 实例。LocalApp 目前按登录用户加密保存配置，并按用户和应用创建 MCP 实例，因此不能直接把该入口挂到根 Context。

本轮不启用社区 MCP 管理器，也不复制其后端。当前界面和接口已从账号插件移入设置插件；以后复用该界面时，需要单独适配保存、实例状态与请求身份。会话通知插件仍为候选，未安装或启用。MinerU 和额外文档服务没有引入。
