# 开发者页面验收与源码恢复

## 使用方式

在应用的开发者对话中展开「验收与版本」。这里分别显示源码版本、构建、开发预览、页面验收和已上线版本，不把编译通过当作页面行为通过。本次源码版本相对前一版本的改动文件和工作区未构建改动分别展示。

点击「执行页面验收」，会使用指定成功构建创建独立测试预览。可以从空测试数据开始，也可以将生产数据复制到该测试预览；自动验收始终只读写测试数据。当前开发预览和生产应用不切换、不重置。

点击「恢复选中源码」，确认后保存当前源码并恢复目标版本。生产应用不会改变。旧预览关闭，旧构建状态清空；重新检查、预览，再决定上线。已经通过平台发布的源码版本会标注对应的上线版本。

## Agent 工具

- `get_current_page`：读取当前应用文字、标记元素实时尺寸和关键样式、父级滚动容器、表头整体及前几行布局。排除表单值、私密区域和平台聊天。
- `run_preview_check`：创建并执行独立测试预览验收。当前源码有新改动时先返回 queued，任务结束、新预览编译成功后自动执行。指定旧构建不能验收当前的新源码。
- `get_preview_check_results`：查询最近验收结果，包括源码和构建 ID、步骤结果、失败原因及需登录读取的截图地址。queued/running 不是通过。

## 验收步骤

最多 20 项，选择器必须在应用中唯一。不提供 JavaScript 执行能力。

```json
[
  {"action":"click","selector":"[data-localapp-test-action=records]"},
  {"action":"scroll","selector":"$page","y":600},
  {"action":"assert","selector":"thead","position":"sticky","minY":44,"maxY":46}
]
```

- `scroll`：选择器对应的元素滚动到 x/y。`$page` 表示应用所在的实际页面滚动容器。
- `click`：仅允许 `role=tab` 或 `data-localapp-test-action` 控件，不点击链接、表单或输入框。应用开发者需给可测试控件添加稳定的标记。
- `assert`：检查 visible、text、position 或顶部位置 minY/maxY。检查真实固定效果时，需要滚动前后比较坐标，不能只检查样式为 sticky。

没有 assert 时仅记录 observed。任一动作或预期失败返回 failed，并记录对应选择器和原因。执行后生成 PNG；截图失败单独显示，不能声称截图成功。网页提交后立即返回任务，页面查询状态，避免长请求超时。

记录绑定项目、源码和构建，最近保留 20 次。截图读取检查当前用户和项目；自动验收预览不能切换到生产读写。Server 重启后的未完成记录明确显示中断。

## 验收边界

一次验收通过只说明提交的步骤通过，不代表所有功能通过。原 outer-ai-usage 示例行修复与表头固定问题仍需使用对应记录页和实际滚动步骤验收，之后才决定上线。

多模态识图能力的单独检测不属于本轮；截图生成、截图下载和模型直接理解图片需要分别验证。
